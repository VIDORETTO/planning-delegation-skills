## Traceability rules

1. copy each `REQ-*` ID, origin, priority, release, oracle, and state from `SPEC.md`; do not create a second requirement identity;
2. preserve candidate origin (`CR-*`) and authoritative source (`SRC-*`), or identify an authorized planner proposal;
3. assign a stable `REQ-*` ID without recycling it;
4. map every active requirement to at least one task;
5. map every task to at least one requirement;
6. define an observable oracle, independently observable vertical-slice value, and applicable security control;
7. update evidence and state without deleting historical origin.
